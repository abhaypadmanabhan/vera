# SLICE A — `p10/polish`: the voice, and the copy rule

### Task A1: Jargon is leaking onto a presentation surface

**Files:** `components/vera/deck-player.tsx:551`, `tests/deck-ui.test.ts`

The summary slide renders `ProofChart evidence={provenEvidence[0]}`, whose title is
`evidence.claim` — verbatim `"date_added is DD/MM/YYYY"`. That is a column name and a date format
on the final slide of the presentation, which `CLAUDE.md` forbids outright and the builder has
raised more than once.

**Why 328 tests missed it:** `tests/deck-voice.test.ts` asserts the jargon regex against
`slide.spoken` and `slide.beats[].spoken` only. Nothing asserts against *rendered* text.

- [ ] **Step 1: Write the failing test** — render every non-working slide and assert the jargon
      regex against its full text content, not just its narration:

```ts
// tests/deck-ui.test.ts
const JARGON = /\b(column|pandas|python|dd\/mm|mm\/dd|day.first|month.first|format|parse[sd]?|dtype|csv|_[a-z]+\b)\b/i;

it("renders no code jargon on any narrated slide", () => {
  for (const slide of deck.slides) {
    if (slide.kind === "working") continue;
    const { container } = render(<DeckSlide slide={slide} finding={VERIFIED_WITH_EVIDENCE} />);
    expect(container.textContent ?? "", `${slide.id} rendered jargon`).not.toMatch(JARGON);
  }
});
```

- [ ] **Step 2: Run it and watch it fail** on the summary slide.
- [ ] **Step 3: Fix.** The proof chart keeps its bars and its counts — they are the proof and they
      stay. Only the *title* changes, from the technical claim to a plain-English label built the
      same way `caveatLine` builds its sentence: what the check was about, not how it was
      expressed. `evidence.claim` stays available on the working slide.
- [ ] **Step 4: Green.** `pnpm vitest run tests/deck-ui.test.ts tests/deck-voice.test.ts`
- [ ] **Step 5: Commit** — `fix(deck): keep the technical claim off the summary slide`

### Task A2: The openers are templated

**Files:** `lib/deck.ts:69-73`, `tests/deck-voice.test.ts`

All three openers share the stem *"Right — I went through this properly, and…"*. That is my
placeholder text from the plan, copied verbatim. It reads like a template because it is one.

- [ ] **Step 1:** Write three genuinely different openings, one per valence. They must sound like
      a person starting a briefing — the builder's examples were *"I did the research and here's
      what I found"*, *"you're not going to like this"*, *"here's the good news"*. Vary the
      sentence shape, not just the tail.
- [ ] **Step 2:** Add a test asserting the three openers share no leading clause.
- [ ] **Step 3: Commit** — `feat(deck): three openings that sound like three different moods`

### Task A3: "What it means" recites a number instead of comparing

**Files:** `lib/deck.ts` (`meaningLine`), `lib/codegen/generate.ts` (the prompt), tests

`meaningLine` currently says *"Set against the same quarter a year earlier, that is 121,004.20."*
That states the second number and leaves the listener to do the arithmetic. An analyst says
*"up nineteen percent on the quarter before."*

**The honest way to get that, and the only one permitted:** the delta must be **computed by the
same script**, not derived in TypeScript from two verified numbers. A figure TypeScript calculates
is still a figure no code produced (PRD §6, and `tasks/definition-of-done.md` §1).

- [ ] **Step 1:** Extend the codegen prompt's context rule so the model is told it may include a
      change-against-a-comparable figure — a percentage or a difference — as its own named context
      entry, computed in the program alongside everything else.
- [ ] **Step 2:** Have `meaningLine` read naturally when the description already expresses a
      change (*"up 19% on the same quarter a year earlier"*) and fall back to today's phrasing
      otherwise.
- [ ] **Step 3:** Test both shapes, and test that a context figure which fails grounding still
      produces no meaning slide at all.
- [ ] **Step 4: Commit** — `feat(deck): say the comparison, computed, not the second number`

**Slice A owns:** `lib/deck.ts`, `components/vera/deck-player.tsx`,
`components/vera/evidence-chart.tsx`, `lib/codegen/generate.ts`, `tests/deck-*.test.ts`,
`tests/codegen-structured.test.ts`.

# SLICE B — `p10/pipeline`: make prep actually do something

### Task B1: Nothing reads the cleaned file

**Files:** `app/api/analyze/route.ts`, `lib/real-analyst.ts`, `lib/types.ts`, `tests/analyze-route.test.ts`

`AnalysisRequest.analysisPath` exists and `lib/real-analyst.ts` honours it. **`/api/analyze` never
sets it.** So prep writes a cleaned file, measures it, reports it — and every answer is still
computed from the raw file. Prep is currently theatre.

- [ ] **Step 1:** Write a failing test proving `/api/analyze` passes the prepared path when a
      `PrepReport` exists for that content hash, and the raw path when it does not.
- [ ] **Step 2:** Look up the report via `getPrep(contentHash(content))` and set `analysisPath`
      when `report.ok`.
- [ ] **Step 3:** Prove the fallback: a missing or evicted report answers from the raw file rather
      than failing the question. **Never fail a question because prep is unavailable.**
- [ ] **Step 4: Commit** — `feat(api): answer from the prepared file when there is one`

### Task B2: The derived columns are invisible to the analyst

**Files:** `lib/prepare/run.ts`, `lib/real-analyst.ts`, `lib/datasets.ts`, tests

Task 11 added `duration_amount`, `duration_unit` and `<name>_list`. But codegen is handed the
**original** profile, so the model never learns those columns exist — and
`lib/codegen/python-policy.ts` rejects any column not in the profile. The Netflix column that
motivated the entire widening still cannot be queried.

- [ ] **Step 1:** Write a failing test: after a prep that splits a mixed unit column, the profile
      handed to codegen contains `duration_amount`.
- [ ] **Step 2:** Re-profile the **cleaned** content and carry that profile on the `PrepReport`.
      Prep already knows what it produced, so this needs no model call and no extra spend.
- [ ] **Step 3:** Thread the prepared profile through to codegen alongside `analysisPath`, so the
      two always agree. A prepared path with an unprepared profile is a bug that will produce
      rejected code.
- [ ] **Step 4: Commit** — `feat(prepare): let the analyst see the columns prep created`

### Task B3: The audit goes dark exactly when it matters

**Files:** `lib/prepare/audit.ts`, `tests/prepare-run.test.ts`

The audit requires identical schemas before and after. Any widened transform adds a column, so on
a messy file — the only kind where widening matters — counts become `null` and Vera says she could
not measure it.

- [ ] **Step 1:** Write failing tests: added columns must not suppress the counts, while every
      existing ambiguity guard keeps withholding.
- [ ] **Step 2:** Compare only the columns present in **both** files for coercion counting, and
      report added columns as their own measured fact.
- [ ] **Step 3:** **Do not weaken a single existing guard.** The audit withholds counts whenever
      row identity is ambiguous, and that behaviour is correct — an unmeasurable count must stay
      `null` rather than become a plausible guess.
- [ ] **Step 4: Commit** — `fix(prepare): measure the file even when prep adds a column`

### Task B4: Mock mode shows nonsense

**Files:** `lib/prepare/generate.ts` (mock only), `lib/prepare/run.ts` (`createMockExecutor`), tests

Two mock-only defects, both visible in a browser right now:

1. Mock questions are built from raw column names — *"What is the total release_year?"* on screen.
   Code jargon on a presentation surface, and semantically absurd.
2. `createMockExecutor` returns empty stdout, so `parseAuditOutput` is always `null` and every
   mock prep ends *"She could not measure the before and after on this file."* The measured-counts
   panel has never been seen on screen.

- [ ] **Step 1:** Make mock questions read like English, phrased from column *kind* rather than
      column *name* — "How many titles are there of each type?" not "How many distinct type
      values are there?". They must still pass `classifyQuestion`.
- [ ] **Step 2:** Have the mock executor return a plausible, self-consistent `VERA_AUDIT:` line so
      the counts panel renders. It is mock data and must stay labelled as such — never let a mock
      count read as a real measurement.
- [ ] **Step 3: Commit** — `fix(mock): plain-English chips and a measurable mock prep`
